# 许可、权利主体、贡献与创作者内容政策

> 本文件是已决定的治理政策，不是替代律师审阅的最终 CLA 或创作者协议。

<a id="SPEC-LICENSE-RIGHTS-CODE"></a>
## 1. 程序代码

新重启基线后的程序代码原样采用 `PolyForm-Noncommercial-1.0.0`。项目权利主体为维护者本人这一自然人；商业用途通过其逐案签发的独立商业许可证获得。

禁止把项目描述为 OSI Open Source 或 FOSS，应使用“非商业源码可用”。

<a id="SPEC-LICENSE-RIGHTS-BOUNDARY"></a>
## 2. 新旧边界

- 旧仓库 Tag 和历史不追溯重许可；
- 旧代码、测试、迁移、文档和素材零迁移；
- M0 必须记录旧 Tag 的实际许可状态；若没有仓库级许可证，记录“未发现仓库级许可/默认权利保留”，不得猜测；
- 新文件从重启基线开始采用新许可。

<a id="SPEC-LICENSE-RIGHTS-ASSETS"></a>
## 3. 资产分离

程序代码、官方内容、文档、商标、第三方素材、用户上传内容分别授权。代码许可不授予官方名称、Logo 或品牌权利。

<a id="SPEC-LICENSE-RIGHTS-CONTRIBUTION"></a>
## 4. 外部贡献

核心包规范和治理完成前不开放外部代码贡献。开放后必须签署 CLA，允许公共非商业发行和项目权利主体独立商业授权；贡献者须声明第三方与 AI 来源。

<a id="SPEC-LICENSE-RIGHTS-CREATOR"></a>
## 5. 创作者内容

只有创作者主动选择平台认证/分发并完成有效书面电子签署时，合格原创内容的 50% 不可分割版权权益转让给项目权利主体。自托管私人导入、草稿、离线预览和私人测试不触发转让。

第三方素材、背景 IP、无权转让部分和权属不明 AI 输出不进入共有。

<a id="SPEC-LICENSE-RIGHTS-COMMERCIAL"></a>
## 6. 商业授权与收入

项目权利主体主导平台发行和商业谈判。涉及共有创作者内容的新商业许可必须先完成逐项商业交易附表；50/50 权益不自动等于固定收入比例。一般平台服务费和内容商业收入分开。

<a id="SPEC-LICENSE-RIGHTS-MORAL"></a>
## 7. 精神权利

保留作者署名。协议可对明确列举的格式转换、技术修复、本地化、审核、无障碍处理和合理改编取得预先书面同意；不得使用无限制放弃或错误署名条款。

<a id="SPEC-LICENSE-RIGHTS-DRAFT"></a>
## 8. M0 法律文件状态

PolyForm 正式文本和许可边界可以落地。CLA、50/50 共有协议、精神权利同意、商业许可模板和交易附表在澳大利亚知识产权律师审核前必须标记 `DRAFT — NOT FOR EXECUTION`，且系统不得接受签署。
